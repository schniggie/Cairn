# Cairn 研究工作台 · 开发总纲

版本：5.2 / 2026-09-09  
状态：前端方案已获继续实现授权；M1 页面与持久化部分已接入，完整执行能力尚未完成  
适用范围：Cairn 漏洞研究产品；本文替代所有旧漏洞模块计划。

## 1. 产品目标

Cairn 保留原有 CTF / 通用任务主功能，漏洞研究作为同一应用中的扩展板块，共用黑板与调度框架。研究工作台面向个人研究者，在 Kali 上运行。用户给出目标与材料，一次确定研究边界，Agent 完成理解、探索、验证、证伪与报告；用户可以观察证据、补充方向、暂停和续跑。

完整链路：输入目标 → 建立研究上下文 → 收集与读代码 → 形成假设 → 使用工具/脚本验证 → 保存证据与结论 → 报告 → 修复后复测。

完成标准是一个用户能够从网页走完的真实流程，不是适配器数量、数据库表数量、任务执行百分比或文档中的完成声明。

## 2. 已确认的需求

1. 个人使用优先。一次项目授权；日常任务、失败重试、暂停恢复不重复授权，不要求寻找第二位审批人。
2. 同时规划黑盒、白盒和联动研究，用户不用提前选择语言、框架或扫描工具。
3. 有 URL/域名/IP 就能做黑盒；有代码目录/仓库就能做白盒；二者具备时可关联研究。
4. Agent 自行识别语言、框架、构建方式与关键入口。语言识别不等于承诺所有生态同等深度；不支持的工具或无法建立的调用关系必须如实解释。
5. 首期联动由用户预先搭建应用，提供环境地址和可选测试账号。自动构建/部署任意目标放到后续。
6. Agent 可以自主读文件、搜索代码、组合工具、编写临时脚本和新验证方法，不限于固定配方。
7. Kali /home/kali/work/Cairn 是权威开发与运行工作树，页面测试也针对 Kali。Windows 只是同步副本。
8. 开发到合适阶段再推送 GitHub；本轮不提交、不推送。
9. 先交互原型，再以用户流程与状态定义接口、Worker 和数据契约。前端不能承诺后端无法解释的结果。
10. 可以果断删除无意义功能；不为兼容过时产品形态而保留复杂性。

## 3. 输入与三种研究模式

| 可用材料 | 系统识别的模式 | 必须能完成 |
| --- | --- | --- |
| 网站/域名/IP | 黑盒 | 建立种子资产、发现接口与交互、提出假设、动态验证、请求响应证据 |
| Kali 本地代码或已准备仓库 | 白盒 | 项目结构与语言识别、入口/权限/数据流审计、文件行号与版本绑定、验证条件说明 |
| 代码 + 已运行环境 | 联动 | 路由/对象/参数映射，源码疑点对应运行请求，基线与变体比较，修复复测 |

同一个项目可追加材料，不需要重新建项目。新增材料属于原授权范围时自动接入；新的范围或更高预算形成一次变更确认。远程仓库自动拉取、私有仓库凭据配置是后续输入便利性，不阻塞本地目录审计。

代码审计不是 Gitleaks/依赖扫描的别名。必须能够解释数据流、权限边界、调用上下文与业务条件。静态疑点不能冒充动态已验证结论。

## 4. 一次授权与个人运行策略

启动时展示可读摘要：目标与排除项、代码目录、运行环境、允许的读取/测试操作、测试身份、时长/请求/费用上限和停止条件。高级项提供合理默认并折叠。

个人模式的项目所有者可以一次确认计划和允许动作，不走双人/逐任务审批。应用登录身份、目标测试身份、模型凭据三者分离，不在普通输入框或本地浏览器存储中保存真实秘密。

执行器继承同一版本的授权快照。暂停和重试继承该快照，不能通过重启刷新预算。确实扩大目标、动作或预算时只询问对应差额；到期则说明原因并等待续期。

自主研究仍需要可靠执行边界：Agent 的项目工作区、文件挂载、目标网络、请求数和进程生命周期由执行层控制。原始网页、代码注释和参考资料不会变成授权来源。不能只删除提示词禁令而放开整个 Kali 宿主机。

不把任意自由文本命令作为前端直接执行 API。研究 Worker 可产生脚本/命令产物，记录工作目录、内容哈希、执行许可、退出结果、产物与证据。未批准的外部目标不进入执行。

## 5. 前端方向：以研究任务为中心

旧“信息收集 / 漏洞挖掘”双主线不再是强制导航。它们合并到研究流程中，用户不需要决定在哪个模块接着做。

主工作区：
- 左侧：项目切换、新建研究与项目材料摘要。
- 中间：目标、运行状态、当前研究方向、过程/发现/资产；按需发出补充指令。
- 右侧：与当前发现相连的证据、代码和请求响应；结论必须可追溯。
- 顶部：一次授权摘要、暂停/继续和报告动作。
- 新建：目标描述、可选网站/代码/运行环境，自动识别模式，一次启动。
- 报告由发现或整个研究生成，不设独立“报告中心”。

默认不显示数据库、Adapter、Lease、Cursor、Job/Task/Run、原始模型 JSON、签名/哈希和审批角色。高级排障能够下钻，但不占据日常工作区。

不展示没有分母和覆盖证明的总覆盖百分比。用“检查了什么 / 尚未验证什么 / 哪些受阻”表达进展。模型的解释是简要决策依据，不展示或索取隐藏思维过程。

前端原型是讨论入口，最终布局可根据用户反馈变更；不在总纲中冻结每个像素。

## 6. 架构取舍

保留并复用：
- FastAPI、SQLite、Cairn Fact/Intent/Hint 与 Dispatcher，沿用成熟能力再逐步抽离耦合。
- Evidence、资产归一化、版本引用、Finding 去重与历史、预算、任务恢复、工具适配器。
- 已有研究经验转为可检索材料，工具/Recipe 是可用能力，不是探索天花板。

增加/重构：
- ResearchSession：目标、材料、授权、状态、当前方向和结果摘要。
- ResearchEvent：计划变化、工具/代码检查、证据、结论、失败、等待输入和恢复的因果事件。
- Research Worker：可访问授权材料及专属工作区，工具调用和临时脚本可观测。
- Execution broker：落实文件、网络、资源和状态变更边界；承接既有 Adapter 与自由研究产物。
- Evidence view：统一代码位置、版本、基线/变体请求、工具输出、截图与复测关系。
- 面向页面的聚合读模型与增量事件接口，避免让浏览器拼接几十张表。

Fact 保存有证据的有限结论；Intent 表达研究目标；Hint 表达人为方向。大量源码/请求/日志留在研究领域，不能直接堆入黑板。

先继续使用现有无构建静态前端完成演示；本轮不引入 React/Next/云数据库等新技术栈。生产重构阶段根据组件复杂度单独决策，不以换框架代替产品改进。不引入 LangGraph/OpenHands 作为依赖，仅借鉴其状态与事件设计。

### 6.1 集成原 Cairn

统一应用入口，保留现有 CTF/通用任务，将新研究工作区接入“漏洞研究”入口。8011 仅用于独立交互评审，正式版回到现有 Cairn 服务与页面路由。

共享 Project、Fact/Intent/Hint、Worker 驱动、配置和进程管理。CTF 与研究采用各自的调度 profile、提示词、工作目录、任务类型和预算，防止相互认领任务。具体路由沿用现有约定并做好旧入口跳转；不通过 iframe 套入整个独立站点作为最终实现。

黑板适合记录跨步骤的可靠发现与探索目标，但 CTF 的拿到 flag 即结束不能直接套到持续研究。研究需要“本轮收束/继续探索”、证据覆盖限制、复测和新的事实。源码、请求和临时输出留在证据域，Fact 只保存有证据支撑的有限结论。

### 6.2 沿用 Kali Claude Code 配置

默认复用 Kali 已安装的 claude 和现有用户级配置，不要求在漏洞板块重复填写 API key、base URL 或模型。当前 dispatch.yaml 与 dispatch.vulnerability.real.yaml 都使用 local + claudecode，Worker env 为空；后者仅在执行环境继承和任务能力上不同。

当前旧漏洞分析命令使用 --tools 空值，且提示词禁止文件/工具操作。这只能做离线分析，不能直接当作新自主研究 Worker。后续复用原驱动的 CLI 调用与会话恢复能力，增加研究任务协议与受控工作区。

保持相同配置来源不等于混用 CTF 会话、材料与预算。显式 profile 覆盖必须可见；变更 HOME、容器或服务用户时需验证配置仍被正确继承。只在 shell 临时会话修改的模型不保证被新后台进程继承；设置文件、环境与命令行的实际优先级需要记录。不要将用户模型秘密复制到网页、项目文件或审计正文。

验证时需实际确认启动的 CLI、实际报告模型、工作目录和任务权限。2026-09-09 已在正式服务同用户、继承环境下完成一次无工具的独立连通性检查：Claude Code 2.1.215 沿用用户级配置返回固定应答，CLI 报告模型 grok-4.5[1m]。检查使用空临时目录与 safe-mode，没有项目材料；不证明第三方网关底层模型身份，也不代表 Research Worker 已接入。研究工具、会话恢复和运行边界仍待真实验收。记录见[实施状态](implementation-status.md#2026-09-09-claude-code-配置继承与独立连通性验证)。

## 7. 删除、合并与保留清单

| 功能 | 决策 |
| --- | --- |
| 个人项目双人审批、逐任务审批页面 | 删除个人模式入口，改为项目授权与必要变更 |
| 七个旧子页面、强制双主线导航 | 合并为研究工作区 |
| 泛统计卡、无依据覆盖率、默认全屏资产图 | 删除默认展示；有明确研究用途才保留具体视图 |
| 每个数据源/任务都要求用户配置与启动 | 改由 Agent 与后台管理 |
| 固定 Recipe 是唯一验证路径 | 移除该限制，保留 Recipe 为稳定方法 |
| 大而全配置页、独立报告中心 | 精简成项目设置和上下文动作 |
| 团队管理、工单流转、平台自动提交、复杂通知中心 | 不进入首个可用产品 |
| 原始证据、发现历史、审计、预算与恢复点 | 保留，删除功能不意味着删除研究数据 |
| CTF / 通用任务 | 保留现有主功能，与漏洞研究并列进入；共享引擎，模式和任务上下文分离 |

删代码前定位调用方与数据依赖；可以移除旧 API，但要明确迁移或替代入口。历史数据库先备份和演练，不因“果断”而销毁用户研究成果。原型保留为独立评审入口；正式研究页已接入原服务，旧数据与原主功能保留。

## 8. 交付路线

### M0：前端 MVP 与开发总纲（已完成）
- 完成社区/官方产品研究，两种模型各给出设计判断，主 Agent 合并。
- 交付 Kali 可访问的独立交互原型，覆盖新建、目标材料、研究过程、发现证据、暂停/继续、补充方向与报告。
- 样例明确标注为演示，不访问真实目标、不调用模型、不读生产数据库。
- 用户体验反馈决定下一轮交互调整；批准的流程成为后端契约基线。

### M1：黑盒 Web 完整产品切片
- 修复种子入库与收集后续链路，工具依赖预检，后台生命周期与真实状态。
- 实现个人授权、研究事件与可用 Research Worker。
- URL → 页面启动 → 探索 → 验证或证伪 → 证据 → 报告。
- 实际检查 Amass/RDAP 等历史失败，不能只依据旧会话认定原因已修复。
- 演示到真实数据切换，不用计时器伪造进度。

### M2：通用白盒审计
- Kali 本地项目目录，自动语言/框架识别。
- 仓库版本与源文件索引、入口与数据流研究、代码位置证据、审计报告。
- Agent 自主补充分析脚本；对未知生态说明限制，不靠固定语言选择器阻挡。

### M3：黑白盒联动
- 用户提供已运行环境与可选测试账号，建立代码/路由/请求映射。
- 静态疑点动态验证；实际基线、对照与结果；修复版本后的针对性复测。
- 动态无法验证时保留为疑点，清晰解释所缺条件。

### M4：可靠性与按需扩展
- 长任务续跑、失败分类与有界恢复、变化触发、经验反馈和成本治理。
- 再考虑自动搭建目标、远程仓库接入、更多工具和专项领域。
- 老4.1“大而全”能力不再要求同时完成；完整产品指上述核心体验完整，不是旧功能清单全保留。

黑盒先行是基于现有代码的交付成本判断，白盒与联动属于已承诺路线；不得无期限后移。

## 9. 页面到后端的契约草案

| 用户动作 | 所需契约 |
| --- | --- |
| 新建与一次启动 | 创建 ResearchSession，保存材料与授权版本，返回持久 session_id |
| 查看研究 | 返回概况、当前方向、可计数进展、最近事件和待补充材料 |
| 实时进展 | 带单调序号/游标的事件流，刷新/重连不重复、不漏持久事件 |
| 暂停/继续 | 幂等状态转换，区分 pause_requested 与 paused，返回实际执行状态 |
| 补充方向 | 追加 Hint 与接收事件，下一轮计划引用该指令 |
| 点击发现 | 返回主张、验证状态、影响、源码/HTTP/工具证据和历史 |
| 查看/筛选资产 | 分页资产与来源，不把种子或执行成功冒充完整覆盖 |
| 报告与复测 | 固定证据版本的报告；复测关联原发现并保留前后结果 |

暂不冻结具体 URL 路径或 schema；在 M0 用户反馈后给出契约样例与状态机，再落入现有服务。

## 10. 验收与真实性

- 首次使用不依赖开发者替用户操作生产数据库或逐项目启动 collector。
- 范围内启动到报告最多一次授权，不出现个人双人审批。
- UI 显示的运行状态来自后端；工具失败、空结果、无权限、缺环境分别可解释。
- 发现分为线索、验证中、已验证、误报/未复现；无漏洞是允许结果。
- 白盒证据绑定文件与版本；动态证据有基线/变体与运行来源。
- 暂停停止新工作，恢复从检查点继续，不隐式重置预算。
- 测试和浏览器验收在 Kali 进行；运行记录写入当前实施状态，不继承旧测试数字。
- 本轮前端演示通过不代表上述后端验收通过。

### 11.1 开发协作方式更新（历史，已由11.2替代）

后续委派开发改用用户提供的本地网页Agent（http://127.0.0.1:3080/），使用DeepSeek Web / Thinking off，不再使用GPT-5.6承担开发。协调Agent负责划定功能块、检查实际代码、集成并在Kali验收。

网页模型有限流，采用单会话串行开发，不要求其另开子Agent或并行模型会话。响应慢时等待同一请求；只有页面/日志明确显示结束、失败或取消，才按对应错误处理，不因等待时间长而重复发起。

Kali权威工作树与Windows同步副本的约定保持适用。转交任务前确认工作区，避免将Cairn任务放进其他项目的旧会话。模型切换不构成绕过平台拦截的授权。


### 11.2 官网对话入口更新（2026-09-09）

用户最新指定直接使用https://chat.deepseek.com/进行开发协作，替代此前localhost Harness入口。用户已授权协调Agent按任务选择快速、专家或识图模式，深度思考按需要开启，不再固定关闭。一般修改优先快速模式；复杂设计或难题可用专家模式；需要理解图像时选择识图模式。继续保持单会话串行、不使用GPT-5.6开发。

官网根据必要代码片段提出补丁，协调Agent检查后在Kali应用和验收；不能假设官网可直接访问本机文件或SSH。只传递与任务相关的代码，不发送凭据或无关私有材料。该入口已用材料搜索状态修复验证，不代表整个项目或自主执行链已完成。
