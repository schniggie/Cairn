# Cairn 前端 MVP / 2026-09-09

关联：[开发总纲](development-charter.md) / [调研依据](design-research.md)

## 设计目标

让研究者知道：正在查什么，已经知道什么，依据在哪里，下一步是什么。一次启动后，大部分时间应当用于理解结果和调整方向，而非管理任务。

## 演示入口

Kali 本地：[打开交互原型](http://192.168.61.129:8011/)  
源码：prototypes/research-workbench/  
原服务：http://192.168.61.129:8000/，本轮不修改其运行行为。

这是交互演示，不访问目标、不读取生产库、不调用模型。三个预置项目的代码、请求、发现和运行记录都是虚构固定数据；新建项目只接收页面输入，不凭空产生发现或语言识别结果。刷新页面恢复预置数据，临时输入不持久保存。

## 主屏

- 项目侧栏：Atlas Notes（联动）、Harbor Web（黑盒）、Ledger Service（白盒）。
- 顶部：研究目标、网站/代码材料、模式摘要、一次授权、暂停/继续、研究报告。
- 中间：研究过程/发现/研究材料，过程按目的归组，工具轨迹默认折叠。
- 右侧：选择发现后展示依据链、关联源码、请求对照。
- 底部：补充研究方向。追加到研究记录，并更新下一步。
- 不使用平均覆盖率、全局大统计卡、管理员 CRUD 导航或默认全屏图谱。

## 可操作流程

1. 切换三个项目，观察不同材料模式：纯网站不显示源码标签；纯代码不显示 HTTP 标签。
2. 在 Atlas 中点“关联源码”和“请求对照”，查看同一个发现的两类证据。
3. 点“发现”，筛选已证实、待验证、已排除；选择后证据工作台同步变化。
4. 点“研究材料”，搜索文件或接口，再进入关联证据。
5. 点“暂停”，先显示正在暂停，随后显示已暂停；“继续研究”不再弹授权。
6. 补充一个研究方向：记录出现在过程，下一步内容改变；暂停时也能保存指令。
7. 点“演示下一步”显式推进演示。样例收束为结果，新项目仅演示阶段，不伪造调查内容。
8. 演示复测：追加复测记录，不发送网络请求，不提升待验证线索为已证实。
9. 打开研究报告，导出包含证据、代码/请求和未覆盖项的 Markdown；也可导出单发现。
10. 新建研究：名称、目标、网站/代码至少一项、一次授权；模式随材料自动推导。高级边界可编辑。
11. “重置演示”清除当前页临时输入，恢复三份预置案例。

## 状态与术语

研究：研究中 / 正在暂停 / 已暂停 / 已结束。  
结论：已证实 / 待验证 / 已排除。  
已证实仍标明证据类型和覆盖边界；正式产品还需“暂无法判断”、等待材料、自主恢复和连接中断状态。运行是否结束与漏洞是否成立独立。

研究阶段是当前关注点，可回到较早阶段；不得据此生成“目标100%安全”。

前端计时器仅用于明确标注的暂停/复测演示，不是未来执行逻辑。真实版本必须由后端确认状态。

## 视觉与响应式

冷灰底、白证据区、石墨侧栏与绿色强调。主正文约16px，操作标签14px，次要元数据12px；等宽字体用于源码/请求。以细线与留白分组，无营销封面、无黑客装饰。

宽屏同时查看研究与证据；1020px 以下证据按需覆盖主屏，点击左侧遮罩空白、关闭按钮或 Escape 收起；遮罩点击不触发底层控件；700px 以下侧栏进入抽屉。弹窗使用原生 dialog，支持 Escape 和焦点约束。动画尊重 reduced-motion。

## 后端接入边界

原型 app.js 中 fixtures() 提供数据，workbench 管理页面状态。正式接入应抽出数据适配层：
- ResearchSession 概况与材料；
- 持久 ResearchEvent 及游标；
- Finding 与 Evidence 引用；
- 启动、暂停、继续、Hint、报告、复测命令。

不要直接把演示定时器换成“假流式”后宣称接入完成。正式接口需要受理与执行状态区分、错误类型、范围/预算执行与刷新恢复。详见总纲第9节。

## 尚待用户决定

本轮交付后收集用户对布局、密度、主次和新建方式的反馈，再冻结首个后端接口切片。尤其检查右侧证据区的常驻价值、材料入口是否足够直观，以及缺材料时的说明是否需要更直接。
